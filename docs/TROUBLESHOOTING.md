# 故障复盘

| 现象 | 已确认事实与边界 | 处理与验证 |
|---|---|---|
| 模型仅输出“检查工具” | 无真实调用，未通过验收 | 独立守护进程采用本地已验证配置后通过；不能推断所有其他协议不可用 |
| npm导入EACCES | 普通用户写root缓存 | 设置服务专用缓存目录，重新注册及验证 |
| connection refused | 新进程尚未就绪 | 确认监听后重试 |
| CLI unauthenticated | 客户端未登录 | 主机内使用受限凭据完成认证；不公开令牌 |
| Semgrep退出-9 | macOS出现，根因未确认 | 保留失败日志；Linux全套验证通过，不将失败写为无漏洞 |
| 退出0但结果为空 | 退出状态不足以验收 | 检查实际方法调用、完整候选覆盖与可信结果 |
| Runtime.exec字符串、normalize路径样例结论冲突 | 原语义不足以支持原验收结论 | 按确认勘误处理，原样例待复核 |
| Compose重建名称冲突 | 现有容器由Docker直接创建 | 先备份、停止、处理名称冲突，不能直接覆盖数据卷 |

排查顺序：组件健康→配置契约→真实工具→证据裁决→模型解释。失败时记录Commit、Run ID、去密后的错误。原始失败记录受控保留，不冒充成功。
