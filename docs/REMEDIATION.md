## 已实现且有回归测试的修复

- 攻击面逐项结算：所有历史计划中的攻击面必须有已读证据摘要或延期理由；延期必须写明限制，运行标记 `PARTIAL`。该检查约束记录完整性，不能机械证明模型读懂了业务。
- 每个判断必须记录 `knowledge_application`；正常模式引用实际取回的知识文件，消融模式显式允许不引用。引用存在不等于知识必然有效，还需要独立对照实验。
- Python 导航使用 AST、导入别名和调用点，分开定义、调用者、被调用者；动态分派等不确定边显式标记 unresolved。其他语言仍是词法导航，不宣称完整调用图。
- 知识卡注明本项目实验来源、快照/运行编号、反例、决策条件及人工介入点；不虚构客户实践或私有数据。

## 实际解决过的工程问题

1. **静态消融被预检归零**：原确定性分析依赖 Git/framework 预检，V2 安全快照不带 `.git`。曾导致对照不能公平反映旧分析能力。现在使用同一快照哈希适配器，保留原分析、Gate 和建议；回归验证既有 VERIFIED 结果和篡改后降级。生产 Engine 不使用这个对照模块。
2. **模型配置被运行器代理覆盖**：agent-compose provider 环境可能覆盖通用模型变量。专用 `CODEAUDIT_LLM_*` 经 `scripts/run-agent.py` 映射给 Engine；缺配置明确失败，避免另一条模型路径悄悄替代审计。
3. **完成状态过宽**：旧版允许读取一个无关文件后结束。现在显式结算所有计划攻击面，禁止引用未读文件、禁止改计划丢失待查项，未查项产生 PARTIAL。仍然需要人工判断证据与攻击面的语义关联。
